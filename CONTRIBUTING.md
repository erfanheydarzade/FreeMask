# Contributing

Contributions are welcome.

## Guidelines

- Keep FreeMask dependency-free unless a dependency is genuinely necessary.
- Keep processing client-side.
- Do not introduce telemetry or external tracking.
- Keep the interface usable on desktop and mobile browsers.
- Prefer small, understandable changes.
- Do not commit generated build output unless it is required for GitHub Pages.
- Test link parsing with both normal links and base64 subscription text.

## Pull requests

A good pull request should:

1. Explain what changed.
2. Explain why it changed.
3. Include testing steps.
4. Avoid unrelated formatting or refactoring.

There is no need to turn a tiny static utility into a 47-package framework. We have suffered enough.
